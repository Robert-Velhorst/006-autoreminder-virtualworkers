## Evidence recorded so far

- The worker queue now uses the manager's work-order comparator and avoids showing the manager's current card as another primary task. A verification intervention also disables that card's timer control in the worker UI.
- The Work Control timer API rechecks worker ownership, held/waiting state, the latest card assessment and the latest pilot intervention inside a transaction before replacing any active timer. Repeated starts of the same running card are idempotent, and worker-supplied card labels cannot replace the saved card identity. A real-MySQL direct-API test covers cross-worker access, held work, an intervention, duplicate starts and a preserved active timer.
- The legacy Express `/api/time-tracking/start` route also checks pilot-worker ownership through the existing assignment or Trello-member path, then checks held/waiting status, the latest assessment and pilot intervention before writing. A real-MySQL HTTP test covers allowed assigned work, unassigned work and a manager blocker. Founder-created entries and other execution actions still need a separate policy audit; this is not a claim that every action is gated.
- The non-manager Now task shows its recorded completion condition, linked source card and timing range where those fields exist. Missing information is not fabricated.
- New deterministic interventions distinguish a source check, an unreconciled report and explicit conflicting claims. Existing snapshots remain compatible and are not rewritten.
- Worker answers now retain separate result, stated deadline, linked source and document location fields. The source is checked against fresh worker-scoped evidence inside the write transaction; the answer remains a worker report, not an automatically verified source fact.
- Repeated excerpts with the same retained source identity and content revision are grouped in the worker view. The deterministic assessment also collapses repeat observations of that source revision while retaining independent records and conflicting versions. Legacy records without a stable identity remain separate.
- Plan proposals now retain a block-by-block comparison with the current same-day plan: added, moved, updated and no-longer-scheduled blocks, their before/after times, reasons and source assumptions. Availability changes are identified separately. The founder review summarizes the changes and identifies older snapshots that lack comparison data. Removal-only proposals now count as changes for the plan decision.
- The worker's Plan My Day page now shows only the plain-language suggested changes, explains that the saved agenda is still authoritative, and keeps technical assumptions out of the worker view. Today's day-plan shortcut shows a suggestion count when the comparison is current. The saved-plan API returns the same content hash used by the manager; the UI hides block details when the plan has since changed or the proposal was applied. No apply control was added, and shadow proposals remain unapplied.
- Gmail portal notices are now tagged as pointers to unread correspondence, not as the correspondence itself. New ingestion does not infer a deadline or create a source commitment from a detected notice. The manager ignores old stored notice deadlines, requires the underlying document to be checked and blocks the dependent follow-up. Existing commitments and histories are preserved; reminder delivery holds legacy Gmail commitments for review when their linked thread contains a portal notice or the source cannot be verified. Isolated MySQL tests cover the old-task and due-reminder paths. The detection is a conservative text rule over Gmail metadata snippets, not a claim that every portal notification or its full contents can be recognized; provider-backed and multilingual cases still need review.
- A dated claim no longer supersedes another claim merely because both came through the same provider. An automatic source revision needs the same retained record identity, a different content revision, the same sender, a newer source date, a non-backdated effective date and an explicit replacement claim; verified human resolutions keep their separate proof-backed path. The old claim remains in history. Unit regressions cover mismatched records, senders, revisions, authority and dates; the MySQL manager suite still passes. A complete per-subject authority policy and live provider cases remain open.
- When retained explicit facts disagree, the worker evidence view now shows the actual opposing values and exact quoted passages side by side with source role/date and a source link when available. Full passages stay available in a disclosure instead of repeating them by default. Missing or unparseable claims never generate an invented comparison. Unit and 390px/1280px Chromium fixture tests cover this view. Card-field versus source discrepancies, graph-only conflicts and large multi-claim cases still need dedicated comparison coverage.
- A founder's reviewed correction is pinned to a worker, source revision and expiry, then reused as scoped guidance on later assessments. A Gmail portal notice, future or expired source, or unverified decision cannot become correction proof, including when a stored fingerprint is repinned to the unsuitable record. Eight unit cases cover creation and later reuse, including source expiry after the review.
- Founder review can now optionally specify a corrected title and completion condition for one existing internal work, verification or follow-up action. The recommendation is stored in a versioned policy envelope inside the existing correction JSON, while legacy condition-only records remain readable; no database migration or historical rewrite is needed. A later shadow run uses the new step only when its card, action ID, action kind, source fingerprint and expiry still match. It never unblocks the action, changes dependencies, sends a message or applies the plan; revocation restores the original recommendation. Cross-topic disagreement about one corrected step blocks that action, while same-topic corrections for different steps remain independent. Unsafe or external-action wording is rejected. This is observable learning of the recommendation, but item 18 remains in progress until case-level task ranking and practice accuracy improve measurably.
