## Implementation

- Preserve all 117 existing canonical schema table definitions, including columns,
  types, indexes, foreign keys and defaults. Import only 14 absent source tables.
- Preserve all 45 historical SQL files byte-for-byte and all journal entries through
  0044. The frozen baseline records SHA-256 values and Drizzle table-definition
  digests in contracts/0045-canonical-baseline.json.
- CREATE TABLE IF NOT EXISTS preserves evidence and initial manager rows.
- Eight information_schema.COLUMNS checks add only absent reliability columns:
  runs: mode, proposalHash, previousPlanJson, appliedPlanHash;
  state: mode, policyRevision, shadowStartedAt, lastSuccessfulAt.
- Seven foreign keys and fifteen ordinary indexes are individually guarded by
  database-scoped metadata checks. Unique keys and primary keys are retained in
  the original table definitions. Existing source tables must already have those
  original keys; preflight checks this explicitly.
- Four queue slots are inserted only when each id is absent. Existing owners,
  tokens and lease expiry values are not updated. No queue requests, manager
  state rows, pilot activation, runs, reviews or trial events are seeded.
- No runner extension or schema parity script change was needed.
- 0045_snapshot.json is generated by drizzle-kit generateMySQLDrizzleJson against
  the consolidated schema. It links to retained 0031, the last existing snapshot.
  It also captures canonical changes 0032-0044 missing from the older metadata,
  without replaying their SQL or fabricating historical snapshots.

### C. Partial migration / direct SQL retry (isolated clone only)

MySQL DDL implicitly commits: a failed migration may leave earlier DDL applied
without a 0045 ledger row. On a separate disposable clone, stop at statement
boundaries after table creation, after some added columns and after some indexes.
Retry with the ordinary runner. Also replay the 0045 statement-breakpoint SQL
directly once on a fully migrated isolated clone to exercise the guards (without
inserting any extra journal row).

Verify no duplicate-object errors, no changes to preexisting values or occupied
leases, and exactly one appended ledger row on runner success. Verify failed
FK/index additions surface errors instead of being ignored. Keep one migration
process only: metadata check plus DDL and slot check plus insert are not a
concurrent-migrator locking protocol.

## Acceptance and unresolved risks

- Run scripts/verify-schema-parity.ts only against the explicitly restored DB.
  Its current success result checks missing tables/columns, NOT full types,
  defaults, keys or extra-table semantics. Supplement it with the metadata audit.
- All existence guards deliberately preserve rather than repair definitions.
  Wrong preexisting types/defaults or a same-named wrong index/FK may be skipped;
  the restored preflight and postflight must reject that drift.
- Existing source tables missing original PK/unique keys are not automatically
  rebuilt. Duplicates/orphans require parent decisions, not data cleanup here.
- New foreign keys retain source CASCADE / SET NULL behavior on future deletes;
  this migration itself performs no deletion.
- New NOT NULL timestamp defaults passed schema validation on MySQL 8.4.11.
  The seven preexisting evidence/manager tables were empty in the restored copy;
  populated historical-manager backfill is not established by this rehearsal.
- Metadata locks and DDL duration on populated tables remain unmeasured.
- Restored and fresh rehearsals passed. Interrupted-DDL recovery, occupied-lease
  fixtures and populated historical-manager backfill remain additional tests.
